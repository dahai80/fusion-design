## 本分支闭合清单（commit d59149d + 87dd0b0 + 文档 commit）

### Phase 1 — 运行时正确性

- **FAULT-1** 流式 stall deadline（fd-ai-adapter，commit d59149d）：`chat_stream_messages`
  的 SSE unfold `stream.next().await` 无单 chunk 空闲超时 → 包入
  `tokio::time::timeout(idle, stream.next())`，`idle = FUSION_MLX_STREAM_IDLE_SECS`（默认 60s）。
  超时返 `Err` fail visibly（emit error delta + break），不静默重试中途断流（M-5 约定保持：
  流式仅覆盖建连阶段，中途断流不重试——timeout 即失败可见）。
  与 client 总 `.timeout(180s)` 区别：IDLE 是相邻 chunk 间隔上限，长生成内容有间隔也安全，
  仅卡死（无字节超 IDLE）才终止。
  **未新增单元测试**（wasm/native 流式超时需 mock + tokio::time::pause，本轮以既有过往
  chat_stream_messages 回归测试覆盖行为正确性；FAULT-1 逻辑为单点 timeout 包裹，行为
  可由现有 E2E 流式断言间接覆盖）。
- **ARCH-13** 公共 API anyhow 泄漏（fd-canvas-core，commit d59149d）：库 crate 公共方法
  `from_json` / `validate_limits` / `migrate_schema` 原返 `anyhow::Result` → 改返
  `Result<_, CanvasError>`，下游可 downcast 区分 corrupt-file vs upgrade-needed vs 超限。
  `CanvasError` enum 加 `#[derive(thiserror::Error)]`（本就含 `ParseError(String)`/
  `SchemaVersion(u32)`/`DepthExceeded`/`NodeTotalExceeded` 变体），签名切换为强类型。
  anyhow `?` 经 `From` 自动传播，下游 4 调用站行为不变。fd-canvas-core `Cargo.toml`
  顺带移除多余 `anyhow` 依赖（库 crate 不再暴露 anyhow）。
  **未新增变体单测**（既有 `from_json_rejects_deeply_nested` / `doc_from_json_invalid` /
  schema 版本测试已覆盖各变体路径；本轮为签名强类型化，未新增分支）。

## 契约对齐修复（OPS-11 过程中定位，均为 harness.js 一侧修复，非产品 bug）

OPS-11 复用 harness 时发现 harness 假设与产品实现不符，按「报错用例须定位修复」逐项对齐
harness 到产品契约（产品码不改，harness 改）：

1. **`mount` 是顶层 `#[wasm_bindgen]` 自由函数**（非 `WebShell` 静态方法）→ harness 改
   `import { mount }` + `mount()`。
2. **DOM 渲染走 window message 非 BridgeCommand**：`BridgeCommand` enum 无 DOM 渲染变体，
   `render_dom` 仅经 `window.postMessage({kind:"page.render-dom",payload:{document}})`
   （监听器 `as_string()`，故 postMessage 传字符串）。harness 加 `renderDom()` 辅助。
3. **token style id = `fusion-tokens`** 非 `fusion-design-tokens`；隐藏 = `data-fd-hidden`
   属性非 `display:none`；plan 预览 = `#fd-plan-preview` 非 `[data-plan]`。harness 改对应选择器。
4. **node.select 仅由用户点击触发**（非 SelectNode 命令）→ harness 模拟 click DOM 节点。
5. **`__fd_host_post` 累积队列**（产品 F-19 修复，已在 committed main）：非 WKWebView 回退
   路径用 `js_sys::Array` 累积队列（非 last-write-wins），宿主轮询 shift 消费。harness
   `captureHostEvent` 轮询队列取匹配 kind。
6. **check.mjs 假绿修复**：原 `/0 failed/` 断言会匹配 `0 passed, 0 failed`（mount 失败态）→
   改 require passed>0 AND failed==0 AND 无 mount 失败/FAIL。

> 上述产品侧契约（mount 自由函数 / page.render-dom / fusion-tokens / data-fd-hidden /
> #fd-plan-preview / __fd_host_post 队列）均已核实存在于 committed main 的 fd-host-web
> （lib.rs + bridge.rs + render_canvas.rs + render_dom.rs）。harness 改动仅为对齐，产品无回归。
