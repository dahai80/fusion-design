# 变更说明 v0.1.7（补丁 — 生产验收差距补齐）

## 背景

对 15 项核心特性做生产发布验收后，发现 P0/P1/P2 共 9 项差距。本补丁按优先级补齐。

## P0 — 数据正确性缺陷（发布前必修）

- `fd-canvas-core`：`PenDocumentDiff`/`DiffEntry` 增加 `page_id: Option<String>`（serde `default`，向后兼容）。
- `diff`：新增 `all_nodes_by_page`，Added 条目记录节点所属页面 ID。
- `apply_patch`：Added 分支按 `page_id` 插入正确页面，不再恒定落入 `pages.first()`（修复多页文档节点错位）；目标页缺失时回退首页并 WARN；Modified 节点未找到时 WARN 而非静默。
- `apply_field_change`：补齐 `kind`/`style`/`children` 三类字段（serde 整体反序列化替换），不再静默丢弃。
- 回归测试：`apply_patch_added_node_keeps_page`、`apply_patch_style_kind_children`。

## P1 — 能力未达宣传

- **图生 UI 真传图**（`fd-ai-adapter`）：`ImageToUiSkill`、`DesignSkills::image_to_ui(_async)` 改为读取草图 base64 经 `chat_with_image` 发送真实多模态请求；读取失败回退文字描述并 WARN。新增 `chat_with_image_sync`（BLOCKING_RT 封装）、`SkillContext::chat_with_image(_async)`。
- **CLI 暴露全部 Skill**（`fd-cli`）：新增 `image-to-ui` / `multi-variants` / `spec-doc` / `page-flow` 四个子命令，覆盖 SpecDocSkill(#14)、PageFlowSkill(#15)、MultiVariants、image-to-ui。
- **版本管理集成**（`fd-canvas-core`）：`VersionedDocument` 内嵌 `UndoRedoStack`，`save_version` 自动入栈，新增 `checkpoint`/`can_undo`/`can_redo`/`undo`/`redo`。回归测试：`versioned_undo_redo_integration`、`versioned_checkpoint_undo`。

## P2 — 能力缺失/文档勘误

- **CLI 默认模型修正**：`fd-cli` 全部子命令默认模型 `qwen3.5`（小写，gateway 404）→ `Qwen3.5-9B-4bit`（gateway 实测可路由）。
- **fd-cli 测试补齐**：原 0 测试，新增 5 个 CLI 参数解析测试。
- **设计规范预设文档勘误**：`CLAUDE.md`「3 presets」→「2 built-in presets（Apple HIG / minimalist admin），robot-sim 规划中」对齐代码实际。
- **反向同步边界**：codegen 正向生成不变；反向已有 `parse-html`（HTML → PenDocument）路径，CLI `parse-html` 子命令可用，作为代码改回设计的双向兜底。

## 多模态负载验证

- 单测 `chat_with_image_sends_data_url`：验证请求体含 `data:image/png;base64,` + `image_url`。
- 单测 `image_to_ui_async_sends_real_image`：验证 `image_to_ui_async` 走真实图片负载（非仅文字描述）。
- **真实 VL 推理 E2E（已跑通）**：`mlx-community--Qwen2.5-VL-7B-Instruct-4bit` 经 gateway 11432 返回 HTTP 200，模型真实理解草图内容。`fd-cli image-to-ui` 端到端产出合法 `.fusiondesign`。

## 图生 UI 输出鲁棒性（商用加固）

- **System prompt 显式 schema**：`image-to-ui`/`image_to_ui`/`image_to_ui_async`/`screenshot_to_ui` 改用统一 `ui_generator_system_prompt()`，显式约束 node schema（`{id,kind,x,y,w,h,text?,fill?,stroke?,children?}`）并提供示例，避免 7B 模型自行发明 `components/type` 等不匹配结构。max_tokens 2048→4096。
- **JSON 修复层**：`repair_model_json` 修复 7B 模型常见语法错误（双冒号 `"k":"":"v"`、键间缺逗号 `"v" "k"`、重复开括号），纯字符串替换无新依赖。
- **括号失衡修复**：`balance_json_braces` 按栈跟踪 JSON 花括号/方括号深度（跳过字符串字面量），处理 7B 模型实测两种截断模式——尾部多余闭括号（`Extra data` 错误）裁剪、EOF 处缺闭括号（`max_tokens` 截断）按栈补齐。使真实 VL 输出可被恢复而非一律兜底。
- **合成兜底**：`synthesize_fallback_doc`——当模型 JSON 彻底不可恢复时，生成含占位节点的合法 `PenDocument`，保证 CLI 不硬失败。商用场景优于向用户抛解析错误。
- 回归测试：`repair_model_json_fixes_double_colon`、`repair_model_json_fixes_missing_comma`、`repair_model_json_trims_trailing_extra_brace`、`repair_model_json_completes_truncated_object`、`synthesize_fallback_doc_is_valid`、`parse_ui_json_invalid_json_falls_back`、`parse_ui_json_missing_nodes_falls_back`、`parse_ui_json_unknown_kind_falls_back`。

## 上游问题（已提 issue + PR，已修复）

- fusion-mlx VL 推理报 `RuntimeError: There is no Stream(gpu, 0) in current thread`：根因 `engines/vlm.py` VLM 模型加载跑在 `get_executor("io")`（2 worker，权重绑定 io 线程 stream），而 prefill 跑在 engine 专属 mlx_executor（不同 stream）→ 跨 stream 访问报错。
  - 已提 issue：dahai80/fusion-mlx#411
  - 已提 PR（已本地验证修复）：dahai80/fusion-mlx#414 — VLM 加载改用单 worker + `_init_mlx_step_thread` 的专用 executor，并经 `AsyncEngineCore(executor=...)` 复用，使 load + vision-prep + prefill 共享同一线程/stream。
  - 验证：文本模型热加载 + 按需 VL 推理 HTTP 200，真实视觉理解，日志无 stream 报错。

## CLI endpoint 环境变量贯通（商用加固）

- **问题**：`fd-cli` 全部子命令 `--endpoint` 默认硬编码 `http://127.0.0.1:11432`，直接 `with_endpoint`，绕过 `FusionMlxClient::new()` 的 `FUSION_MLX_BASE_URL` 解析 → 用户无法经环境变量切回直连 11434，与 CLAUDE.md 文档不符。
- **修复**：`FusionMlxClient::resolve_endpoint(cli_endpoint)` 新增——空串读 `FUSION_MLX_BASE_URL`、缺省回退 11432；非空串透传（显式 `--endpoint` 优先级最高）。CLI 全部 8 处 `--endpoint` 默认改空串，7 处构造改经 `resolve_endpoint`。`check-mlx` 打印解析后 endpoint。
- **优先级**：显式 `--endpoint` > `FUSION_MLX_BASE_URL` > 默认 11432。
- 回归测试：`resolve_endpoint_empty_falls_back_to_default`、`resolve_endpoint_explicit_overrides_env`；CLI 解析测试断言更新为空串默认。
- 运行时验证：`check-mlx` 三场景（空→11432 / env→11434 / 显式→11432）均符合优先级。

## 商用差距补齐（不再独立排期）

- **安全护栏**（`fd-canvas-core`）：`PenDocument::from_json` / `VersionedDocument::from_json` 反序列化后校验嵌套深度 ≤64、节点总数 ≤100000（`validate_limits` + `count_depth`），防恶意/损坏 `.fusiondesign` 栈溢出/OOM。`fd-ecosystem` IPC `consume` 加 8MB 文件大小护栏。回归测试：`from_json_rejects_deeply_nested`、`validate_limits_accepts_normal_doc`。
- **E2E 自动化测试**（`fd-ai-adapter`）：基于 `tokio::net::TcpListener` mock server（无需真实模型）固化三条生产路径——尾部多余括号修复产出真实文档（不兜底）、彻底损坏 JSON 优雅合成兜底（不硬失败）、HTTP 5xx 向上传播（不静默吞）。`image_to_ui_e2e_trailing_brace_repaired`、`image_to_ui_e2e_garbled_falls_back_gracefully`、`image_to_ui_e2e_http_error_propagates`。
- **性能基线**（`fd-canvas-core`）：`perf_baseline_1000_nodes`（`#[ignore]`，`cargo test --release -- --ignored perf_baseline` 运行）——1000 节点 serialize/deserialize/compute_layout 各 <500ms（实测 release Apple Silicon 均 <1ms）。
- **错误/可观测性 UX**（`fd-cli`）：`report_error` 把 anyhow 错误分类为商用级提示（鉴权失败/服务不可达/上游错误/文档超限/模型返回空/运行错误），输出「分类 + 原因 + 建议」三段，替代裸栈。运行时验证 401 路径输出正确。
- **打包发布**（`Scripts/build.sh`）：一键产出 `dist/fusion-design-<version>-aarch64-apple-darwin.tar.gz`（CLI 二进制 strip+lto + fd_host_web.wasm + VERSION/README.md/INSTALL.md）。实测产物 4.4M。
