# v0.1.28

## Summary

Issue #43 closure: shell-manifest registration in `start.sh` now sends admin auth — the `fusion-design` module actually registers with the gateway and becomes reachable end-to-end from the shell/Design Hub.

## Changes

- **`register_shell_manifest()` sends `Authorization: Bearer <admin key>`** (previously unauthenticated, so every registration was rejected and silently logged as "skipped"). Key resolution matches fusion-supervisor `env_map.rs` / fusion-cowork: `FUSION_ADMIN_KEY` env first, then gateway config `web_shell.admin_key` (`FUSION_GATEWAY_CONFIG` overrides, default `~/fusion/fusion-gateway/config.yaml`). The key is never logged or echoed.
- **Failure modes are distinguished in the log** instead of one opaque "skipped" line: `401/403` (auth rejected — key mismatch), `404` (endpoint absent), connection failure, other HTTP errors, and success. This is what let the live auth bug hide since v0.1.27.
- **Robustness fix**: `set -e` aborted the whole `start` flow when the registration `curl` failed (observed live as exit code 7 with no log line); the call is now failure-tolerant and always logs the classified reason.

## Verification

- Live E2E (2026-11-11): `./start.sh stop && ./start.sh start` → `shell manifest registered at http://127.0.0.1:11432`; gateway `shell_manifests.json` grew 11 → 12 modules with `fusion-design` present; `GET /shell/fusion-design/workbench.html` and `/shell/fusion-design/api/health` through the gateway return 401 (unified login enforced — route exists, serves after site login per issue #28 inline-401 contract).
- Key resolution unit-checked: config-derived key (48 chars) and `FUSION_ADMIN_KEY` override both resolve; key never printed.
- No Rust code change; version bump only refreshes `Cargo.lock` workspace versions (14 lines, no dependency drift).
