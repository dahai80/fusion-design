# v0.1.19 (2026-11-02)

Patch release: workbench UI aligned with the fusion-web-shell design language. Trigger: with the Design module now registered in the gateway shell (`/shell/fusion-design/`, server-side config), the workbench rendered as a foreign surface inside the unified shell.

## What was wrong

- Own light-default theme against the shell's dark default UI
- Indigo `#6366f1` accent vs shell brand `#4f7cff`
- 12-16px radii vs shell 8px card radius; different shadow scale
- Emoji icons (🌙 🖥) vs the shell's icon language
- Duplicated brand topbar inside the module iframe (double chrome)
- Export row: four buttons crammed horizontally in a 248px column

## Changes

- **Design tokens mirrored from `@fusion/design-tokens`**: `--fs-bg`, `--fs-bg-elevated`, `--fs-bg-muted`, `--fs-border`, `--fs-text-*`, `--fs-brand` (`#4f7cff`), `--fs-success/error`, `--fs-radius-card` (0.5rem), `--fs-font-sans` (Inter/system-ui/PingFang SC). Dark default (`color-scheme: dark`); `html.light` switches to the light palette with the same values the shell uses.
- **Theme inheritance inside the shell**: the workbench reads the parent shell's `html.light` class (same-origin iframe through the gateway proxy) and observes parent class mutations, following live shell theme switches; falls back to localStorage when standalone.
- **Slim 44px toolbar** replaces the brand topbar: segmented viewport switch (iPhone/iPad/Desktop, inline SVG), health chip with status dot, compact language select and theme toggle.
- **Surfaces**: cards at 8px radius with token borders; version list items with hover border; active version in brand-soft tint.
- **Export buttons** into a 2x2 grid — labels no longer squeeze.
- **Empty canvas** becomes a dashed drop zone with icon + hint instead of bare centered text.
- Styled scrollbars; narrow-width degradation stacks columns below 900px (previously only width tweaks).

## Scope

UI/CSS/JS only (`crates/fd-server/src/web/{index.html,app.css,app.js}`). No API or Rust logic changes. 519 tests, deny gates and clippy unchanged and green.

## Fix: module-relative assets (2026-11-02)

First cut of the restyle still rendered unstyled inside the gateway shell — reported as "looks like CSS never loaded". Root cause: `index.html` referenced `/app.css` and `/app.js` with **absolute** paths, and `app.js` fetched `/api/...` absolutely. Inside the shell module the page is served at `/shell/fusion-design/`, so those requests hit the gateway root (`http://127.0.0.1:11432/app.css` → 404) instead of the module upstream; the shell proxy strips the `/shell/<id>/` prefix before forwarding, so only relative paths reach fd-server.

- `index.html`: `href="app.css"`, `src="app.js"` (relative).
- `app.js`: `BASE = new URL(".", import.meta.url).pathname`, `url(path)` helper; all API calls, the `fd_host_web.js` dynamic import and the wasm binary URL resolve through `BASE`. Standalone on `127.0.0.1:11493` base is `/`; inside the shell it is `/shell/fusion-design/`.
- Regression test `assets_and_api_are_module_relative` asserts no absolute asset refs and no `fetch("/api`.

Verified through the gateway with a session token: `/shell/fusion-design/`, `app.css`, `app.js`, `fd_host_web.js`, `api/health` all 200 and the served CSS carries the `--fs-*` token set.
