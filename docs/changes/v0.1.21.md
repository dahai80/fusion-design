# v0.1.21 — Artifact 查看器（就地预览，不跳外部应用）

Release date: 2026-11-02

## Why

v0.1.20 的落地页点卡片会重新打开工作台并再生成一次，既慢又丢上下文。
Claude 的形状是「列表里点开就就地看到产物正文」，需要产出与查看同一页完成。

同时回答了「对话框建文档/PPT 与 fusion-office 的关联」：不做应用切换。
fusion-office 是独立工程、独立模块、hash 路由且无提示词入参，跳过去要跨上下文；
本版本改为在 Design 模块内就地预览，Office 格式留作导出出口（上游导入契约另提 issue）。

## What

- 新增查看器页 `artifact.html` + `artifact.js`：
  - `GET /api/artifact/<id>[?version=N]` 取元数据与正文，转发本机
    artifacts-engine（127.0.0.1:11451）。
  - HTML 正文经 `<iframe sandbox srcdoc>` 渲染（禁脚本执行）；非 HTML 走纯文本。
  - 头部：返回落地页、标题、kind 徽章、版本 + 时间、下载、`在工作台继续`。
  - 引擎不可达时降级为可见错误提示，不 500。
- 落地页卡片点击改为 `artifact.html?id=<id>`（不再重复开对话）。
- **修复重复入库**：`存 Artifacts` 原先既写 IPC 又经 REST 建产物，而
  artifacts-engine 自带 IPC 消费者会从同一目录再建一条 `type=data` 产物，
  每次保存出现两条记录。现改为 REST 优先、成功不写 IPC；仅引擎不可达时
  回退写 IPC（引擎恢复后补入库），响应带 `engine_degraded: true`。
- `ArtifactsClient::get` / `content` / `get_json`：补齐单产物读取。
- 资源全部模块相对路径，经 gateway `/shell/fusion-design/` 代理正常加载。

## Verification

- `cargo fmt --all --check` / `cargo test --workspace` / `cargo clippy --workspace --all-targets -D warnings` 全绿。
- 三道离线门禁通过（deny-panic / deny-unwrap-expect / deny-external-http）。
- 本机实测：`art_c4iyzixv` 正文经 `/api/artifact/art_c4iyzixv` 返回 HTML；
  经 gateway `/shell/fusion-design/` 的 `artifact.html`、`artifact.js`、`app.css`、
  `api/artifacts`、`api/artifact/<id>` 全部 200。
