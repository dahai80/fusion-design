# v0.1.24

## Summary

Issue #34 closure: stable-prefix prompt assembly + region-based iteration for long design docs. Fixes the iteration context blow-up on large documents and the model-echo parse dead-loop.

## Changes

### Stable-prefix prompt ordering (`crates/fd-server/src/prompt.rs`, new)

- New `prompt` module owns iterate prompt assembly, aligned with fusion-mlx `enable_prefix_cache`:
  - System prompt is a constant (`ITERATE_SYS`) — cacheable stable head, never spliced with per-request content.
  - User message order is fixed: TOC → changelog → base JSON → instruction (volatile last).
- `toc_of` — one line per node (`page/id kind name`), cross-page summary; the model sees document structure without the full JSON.
- `changelog_of` — last 8 version labels (already recorded as `迭代：{instruction}` by `push_version`, mechanical derivation, no extra model call); older versions fold into one summary line.

### Region-based iteration (O(region) instead of O(doc))

- `POST /api/iterate` accepts `region: [node_id, ...]`:
  - Only the selected nodes' JSON is sent (plus full TOC); server returns 400 if no node matches.
  - Model contract: output only those nodes under `{"page":{"nodes":[...]}}`.
  - Server merges results deterministically (`merge_region_nodes`): positional replacement of region nodes, extra output nodes appended to the first page, all unlisted nodes guaranteed unchanged (Rule 5: merge decided by code, not the model).
  - Empty model output → 502, never silent node dropping (fail visibly).

### Parse/serialize round-trip fix (`crates/fd-skills`)

- Root cause found in live verification: documents serialize `kind` as PascalCase (`"Text"`), while `parse_node_with_depth` accepted lowercase only. The model echoes its input JSON verbatim (`"kind":"Text"`), so region iteration could never parse — a round-trip dead loop.
- Fix: kind matching is now case-insensitive (`rect|circle|text|image|group` in any case). Regression test `parse_ui_json_kind_case_insensitive` added.
