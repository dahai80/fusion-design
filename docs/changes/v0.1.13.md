## 已落地

### OPS-8 — CI wasm-bindgen-cli 版本固定

- **根因**：`.github/workflows/ci.yml` release-pack job 用 `cargo install wasm-bindgen-cli`
  （无版本固定），上游发新版会与 `wasm-bindgen` runtime 版本不匹配，产出 `_bg.wasm`/`.js`
  失败或产物漂移，studio 同步回退陈旧内置件。
- **修**：CI 固定 `wasm-bindgen-cli 0.2.126`（对齐 `wasm-bindgen` runtime 版本），消除版本漂移。
- 落地：`.github/workflows/ci.yml`（`cargo install wasm-bindgen-cli --locked --version 0.2.126`）。

### OPS-13（半）— WASM 诊断环形缓冲

- **根因**：`fd-host-web`（cdylib，无 `tracing` dep，wasm 体积约束）仅
  `web_sys::console::log_1` 实时输出，WKWebView 重载即丢失，崩溃前现场无捕获。
- **修**：`fd-host-web` 加 `LogRingBuffer`（thread_local `RefCell<VecDeque<String>>`，
  定容循环覆盖，`LOG_RING_CAPACITY = 200`）+ `fd_log_error` / `fd_log_warn` 双写
  （console + ring buffer）。崩溃后 `log.capture.dump` 类消息桥经 JS 侧导出 ring buffer 全文。
- 落地：`crates/fd-host-web/src/lib.rs`（LogRingBuffer / fd_log_* + 7 error / 2 warn 站点
  迁移）+ `crates/fd-host-web/src/bridge.rs`（`log.capture.dump` 派发 arm 导出 LOG_RING）。
  随 ARCH-10 bridge 拆分同 commit（698f69a）落地。
- 注：fd-host-web 无 `tracing` dep，用 `web_sys::console`，ring buffer 是该 crate 专属诊断件。

## 未落地（据实说明）

### OPS-13（另一半）— fd-cli 文件日志

- **原计划**：`fd-cli` 加 `init_logging()` + `tracing-appender 0.2` 日轮转日志写
  `~/Library/Logs/fusion-design/`，`FUSION_LOG_DISABLE_FILE` 禁文件日志，`dirs 5` 解析日志目录。
- **实际**：**从未开工**。`git log -S 'tracing-appender'` / `-S 'dirs' -- crates/fd-cli/Cargo.toml`
  全历史（含 all 分支）零命中——既无 `tracing-appender`/`dirs` 依赖声明，也无
  `init_logging` / `resolve_log_dir` / `FUSION_LOG_DISABLE_FILE` 代码。先前文档误称「依赖
  先声明、实现未跟上」属杜撰，实为纯未做（无 deps、无 code、无 env 变量）。fd-cli 诊断
  走 stderr（现状），无文件持久日志。
- **处置**：无需「移除孤儿依赖」（本就不存在）。`FUSION_LOG_DISABLE_FILE` 无对应代码，
  环境变量表（README/TROUBLESHOOTING，OPS-16 本 v0.1.14 落地）据实不录入。先前文档若曾
  列该变量，属误录，已按 OPS-16 单一真相源纠正。
- **后续**：若需 fd-cli 持久日志，按新需求从零做（依赖声明与实现同 commit 落地）。
