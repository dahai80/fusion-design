# v0.1.32

## Summary

Issue #50 closure: nightly-eval design regression (nightly-20261127, 90.0% vs 100.0% floor) traced to two distinct root causes and fixed.

## Changes

- **Restored eval-pinned user-facing strings** (d12/d29 regression, PR #49 fallout): the source-wide English-only pass translated user-facing product strings the eval suite pins — the `/api/version` 400 payloads (`版本号非法（须为正整数）`, `路径须为 /api/version/<session>/<version>`) and the mutate version label (`编辑：<node_id>`). The English-only rule covers comments/logs only; user-facing contract strings are exempt. Strings restored.
- **Contract pins added** so a future translation pass cannot change them silently: `router.rs` `ERR_VERSION_BAD_NUMBER`/`ERR_VERSION_PATH_SHAPE` consts + `version_path_error_strings_are_pinned` test; `handlers.rs` `GENERATE_LABEL_PREFIX` const + `generate_version_label_prefix_is_pinned` test; `contract_node_mutate` now asserts the pushed version label is `编辑：<node_id>`.
- **start.sh key warning** (d28, environment): the eval-time server was launched without `FUSION_CLIENT_KEY`, so every `/api/generate` returned `fusion-mlx HTTP 403` (documented in the d29 transcript, where the agent itself diagnosed it and restarted with the key). `start.sh` now warns at start (stderr + log file) when `FUSION_CLIENT_KEY` is unset.

## Verification

- PR #51 full CI green (fmt/clippy/test/wasm, check+test macos, deny×3, cargo-audit, docs validate).
- 576 workspace tests green (2 new contract pins).
- Restored strings verified against `fusion-eval` `results/nightly-20261127/` recorded baselines (d12 rec payloads, d29 rec label).
