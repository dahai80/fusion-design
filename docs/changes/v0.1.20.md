# v0.1.20 (2026-11-02)

Feature release: the Design module entry becomes an **Artifacts landing page** (Claude-parity shape), and "存 Artifacts" now really creates artifacts in `fusion-artifacts-engine` instead of only writing an IPC message nobody consumed.

## Landing page (module entry `/`)

Clicking Design in the shell now lands on an artifacts page instead of dropping the user into an empty chat:

- **Tabs**: 全部 / 我的 / 与您共享 (`tab=all|mine|shared`).
- **Tools**: search toggle + search box (debounced), sort select (最近打开 / 创建日期 / 名称 / 置顶优先), language and theme toggles. Theme still inherits the shell's `html.light` when embedded.
- **创建新内容**: three cards — 文档 / 幻灯片 / 设计 — each routes to the workbench with the prompt pre-filled and the cursor at the end, waiting for the user:
    - 设计 → `Make a Design artifact for `
    - 文档 → `Make a Document artifact about `
    - 幻灯片 → `Make a Slides artifact about `
- **所有 Artifacts**: responsive card grid (name, kind, summary, updated time, version, pinned badge), item count, previous/next pagination.

The workbench moved to `workbench.html`; the toolbar gained a back arrow to the landing page and keeps the module-relative base path (`import.meta.url`) so it still works behind the gateway shell.

## Real artifact ingestion

`POST /api/save-artifact` used to write only a `save_artifact` file-IPC message; artifacts-engine had no consumer, so saved designs never appeared anywhere. It now:

1. writes the IPC message as before (historical contract kept),
2. generates the HTML export and calls the engine REST `POST /api/v1/artifacts/create` with `kind` mapped from the create card (`design→app`, `document→document`, `slides→template`).

The engine write is best effort: if the engine is unreachable the IPC write still succeeds and the response carries `engine_degraded: true` plus the error, so the UI can say so instead of silently pretending.

## Backend

- `fd-ai-adapter::artifacts` — new `ArtifactsClient` (`from_env`, `list`, `create`), 127.0.0.1-only (`validate_localhost`), `X-API-Key` + `Bearer`, 800ms connect / 5s total timeouts. Key resolution: `FUSION_ARTIFACTS_API_KEY` → `security.api_key` in `FUSION_ARTIFACTS_CONFIG` or `~/.fusion/artifacts/config.yaml`. Lives in fd-ai-adapter because the offline gate forbids outbound HTTP crates elsewhere.
- `GET /api/artifacts` (fd-server) — proxies the engine list with `page`, `page_size` (≤100), `sort` (allowlisted), `q`, `type`, `tab`. Engine down → `200 {artifacts:[], degraded:true, error}`; the landing page still lets you create.
- `tab=shared` limitation: the engine has no "shared with me" filter. The handler takes one page of 100 and filters `share_id` locally; the UI labels it as "single-tenant local: shows artifacts you have shared out".
- `tab=mine` maps to the engine's `ownership_type=free` (personal artifacts, not project/cowork owned).

## Fixes found while wiring

- `.hidden` had no CSS rule, so `canvas-empty`, the paste hint and the pending-image chip were never actually hidden. Added `.hidden { display: none !important; }`.
- Query decoding for the search box pushed percent-decoded bytes as chars, mangling CJK (`登录` → `ç»å½`). Now assembles bytes and decodes UTF-8.
