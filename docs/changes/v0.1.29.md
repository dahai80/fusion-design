# v0.1.29

## Summary

Issue #44 closure: design-intelligence data layer — curated offline CSV datasets, a new zero-dependency-surface search crate (`fd-search`), a CLI `search` subcommand, an fd-server search API, automatic generation-context injection, and a CI-enforced data-QA provenance harness.

## Changes

- **New crate `fd-search`** (implements the issue's `fusion-design-search` proposal, named per workspace `fd-*` convention): loads six curated datasets embedded at compile time (offline hard constraint), deterministic keyword scoring across styles/palettes/font_pairings/ux_guidelines/charts/stacks, plus one-shot `recommend(prompt)` returning a `[Design intelligence]` context block. Zero HTTP, zero model calls.
- **Datasets** (`datasets/`, authored in-repo — no upstream CSV content vendored): 24 styles, 24 palettes (8 semantic hex slots each, every palette has a dark bg), 20 Google-Fonts pairings with license fields, 40 UX do/don't guidelines, 12 chart-type mappings, 16 per-stack notes. Schema pattern inspired by ui-ux-pro-max-skill, slimmed to consumed columns.
- **Data-QA harness in CI**: `datasets/provenance.json` (schema version, sources, per-file rows + sha256); the fd-search test suite verifies every entry against embedded bytes on every `cargo test --workspace` run — an edited CSV without a provenance refresh fails the build.
- **fd-server**: `GET /api/design-intel/search?q=&kind=&limit=` (400 `field:"q"/"kind"`, limit clamped 1-50); `POST /api/generate` appends the `[Design intelligence]` block server-side when the prompt matches — no flag, deterministic. Router/known_api_path/docs/API.md/contract tests synced (4-place rule).
- **fd-cli**: `fusion-design search --kind <styles|palettes|font_pairings|ux_guidelines|charts|stacks|all> --query <q> [--limit N] [--json]`.
- **MCP note**: no bespoke MCP tool layer (H-A3/P2-2 precedent — the in-tree MCP stack was removed as non-compliant); the same query surface is exposed via the fd-server endpoint and CLI for agent pipelines.
