# v0.1.31

## Summary

Issue #48 closure: English-only source cleanup — the largest workspace violation (Chinese comments across 63 `.rs` files) removed — plus two gate-ecosystem fixes and the url 2.5.9 RustSec bump.

## Changes

- **English-only source cleanup** (#48 P1, PR #49): translated all Chinese comments, doc-comments, log/diagnostic messages, and error strings to English across all 15 crates, plus workspace/crate `Cargo.toml` comments and description fields. No logic changes; test assertions matched against translated strings updated in lockstep. Remaining CJK in `.rs` is intentional and marked: LLM prompt strings in fd-skills/fd-cli (`// i18n: user-facing`), builtin skill labels, scene-template names, design-system preset names, UTF-8/multibyte regression fixtures, and detectors.rs CJK keyword matching data (translating would change detector behavior).
- **unwrap-expect allowlist realignment**: the two fd-ai-adapter `.expect()` entries carried the pre-translation Chinese panic messages, so the gate saw the translated sites as new violations; entries re-pointed at the translated strings, stale comment block translated.
- **RustSec**: url 2.5.8 → 2.5.9 (RUSTSEC-2026-0592, stack overflow in `Url::origin()` on nested `blob:` URLs); `cargo audit` exits clean, zero `audit.toml` ignores.
- **Doc drift** (#48 P2): monorepo `CLAUDE.md` crate count corrected 13 → 15 (fd-search pushed the workspace to 15 in v0.1.29).

## Verification

- PR #49 full CI green: fmt/clippy/test/wasm, check+test macos, deny×3, cargo-audit, docs validate.
- 574 tests green; `cargo check` / `cargo audit` clean on the merge commit.
- #48 P2 third finding (cold `cargo check` crates.io timeout after `target/` removal) — transient network condition, confirmed self-healing on retry; no code change required.
