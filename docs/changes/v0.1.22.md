# v0.1.22 — 修复存 Artifacts 重复入库

Release date: 2026-11-02

## Bug

`POST /api/save-artifact` 同时做了两件事：

1. 写 `save_artifact` IPC 消息到 `$FUSION_DESIGN_DATA_DIR/fusion-artifacts-engine/`；
2. 经 `POST /api/v1/artifacts/create` 直接建产物。

fusion-artifacts-engine 默认启用 IPC 消费者，轮询的正是同一个目录，于是每次
保存会落两条产物：一条 REST 建的 `type=html`（有正文、可看），一条 IPC 消费者
建的 `type=data`（正文是原始 PenDocument JSON）。落地页因此出现重名卡片。

## Fix

- REST 优先：建产物成功即不写 IPC（响应 `ipc_written: false`）。
- 仅当引擎不可达（连接失败 / 鉴权失败 / 5xx）时回退写 IPC，由引擎恢复后补入库，
  响应带 `engine_degraded: true` 与 `error`，`ipc_written: true`（fail visibly）。
- 新增单测 `save_artifact_falls_back_to_ipc_when_engine_down`：引擎指向无监听端口，
  断言回退分支同时落 IPC 并标记 degraded。

- `cargo fmt --check`、`cargo test --workspace`（530 passed）、
  `cargo clippy --workspace --all-targets -D warnings`、三道离线门禁全绿。

  `type=html / kind=app`，`~/.fusion-design/fusion-artifacts-engine/` 无新 IPC 文件，
  无第二条 `type=data` 重复项；经 gateway `/shell/fusion-design/api/artifact/<id>`
  读取正文正常。
